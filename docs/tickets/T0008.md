# T0008

Title: Improve signup password feedback and blocked-submit messaging
Domain: Auth
Type: UX
Priority: P1
Estimated size: S
Owner type: frontend
Problem: The signup form can block account creation when the password is invalid, but the UI does not clearly show which exact requirements are still missing.
Goal: Make password validation feedback explicit, visible, and understandable before and during submit.
Scope: Signup form UX only. No backend validation rule changes.
Allowed files:
- `src/app/(auth)/signup/page.jsx`
- `docs/tickets/T0008.md`
Do not touch:
- `src/app/api/signup/route.jsx`
- auth validation rules in shared libs
- unrelated auth screens
- dependencies
Acceptance criteria:
- invalid password requirements are shown inline in red
- the password input gets an invalid visual state when requirements are missing
- blocked submit messaging tells the user to fix the listed password requirements
- server signup errors are visible in the form as well as toast notifications
- no backend validation behavior changes
Manual verification:
- confirm each missing password rule appears when that rule is not satisfied
- confirm the success state appears once all requirements are met
- confirm submit remains blocked until the password is valid
- confirm server-side signup errors still show clearly
Commands to run:
```powershell
npm run lint
npm run build
```
Risks:
- feedback can become noisy if too many error states are shown at once
Dependencies:
- none
Rollback plan:
- revert the signup page UI changes if they create confusion or regress form behavior
