# T0003

Title: Add route timing logs for hot endpoints
Domain: Platform
Epic: EPIC 00: Platform Governance and Baseline
Type: perf
Priority: P0
Estimated size: S
Owner type: backend
Problem: Hot paths are known to be slow, but timing capture is incomplete and inconsistent.
Goal: Extend the existing env-gated route logger so the main hot endpoints can be timed consistently.
Scope: Instrumentation only. Do not change endpoint contracts or implement performance refactors.
Allowed files:
- `src/lib/api-debug.ts`
- selected route handlers under `src/app/api/`
- `docs/performance/baseline.md`
- `docs/Known_Issues_And_Followups.md`
Do not touch:
- `src/app/(pages)/`
- `src/app/components/`
- `prisma/`
- dependencies
Acceptance criteria:
- route timing remains behind an env flag
- selected hot routes emit handler and major-step timings when the flag is enabled
- no API response shape changes are introduced by the instrumentation
Manual verification:
- run the app with `DEBUG_API_TIMING=1`
- hit the instrumented routes and confirm timing output appears
- run again without the flag and confirm the logs stay quiet
Commands to run:
```powershell
$env:DEBUG_API_TIMING='1'
npm run lint
npm run build
```
Risks:
- log noise if instrumentation is added too broadly or left ungated
Dependencies:
- `T0002`
Rollback plan:
- remove the added route-logger calls or disable them through the env gate
